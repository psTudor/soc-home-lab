## Brief Description

SQL Injection allows an attacker to insert malicious SQL code
into the input fields of a web application. If the input is not sanitized,
the database executes the injected code, potentially leading to data
exposure or authentication bypass.

---

## Steps Taken

1. Launched Burp Suite and configured proxy on Firefox
2. Accessed http://[VM-IP]:80/#/login
3. Captured the login request in HTTP History
4. Ran SQLmap with the following command:

```bash
sqlmap -r ~/login.txt \
       --level=3 \
       --risk=2 \
       --dbms=sqlite \
       --batch \
       --ignore-code=401 \
       --dbs
```

5. SQLmap confirmed the vulnerability and identified the database backend
6. Performed manual authentication bypass using payload: `' OR 1=1--`
7. Recorded end time and moved to Sentinel for detection analysis

## Detection in Sentinel

### KQL Query Used

```kql
NginxAccess_CL
| where RawData contains "'"
    or RawData contains "OR 1=1"
    or RawData contains "--"
    or RawData contains "UNION"
| extend AttackerIP = extract(@"^(\S+)", 1, RawData)
| extend Request = extract(@'"([^"]+)"', 1, RawData)
| extend StatusCode = extract(@'" (\d{3}) ', 1, RawData)
| project TimeGenerated, AttackerIP, Request, StatusCode
| order by TimeGenerated desc
```

approximately X minutes. The KQL query identified X suspicious requests
